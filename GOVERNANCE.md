# Governance

Cited uses a lightweight maintainer-led governance model during early
open-source preparation.

## Roles

- **Maintainers** set product direction, release policy, and merge readiness.
- **Contributors** propose changes through issues and pull requests.

Maintainer identities will be listed when the public repository is created on
GitHub. This phase does not name individual maintainers.

## Decision making

Maintainers determine:

- Whether a change aligns with the public core roadmap
- Whether documentation, tests, and review standards are met
- Whether a change is safe to merge before publication or release

Security and privacy concerns take priority over feature work.

Breaking changes require documentation updates and clear migration notes when
applicable.

## Roadmap relationship

The public core and Cited Cloud may follow different roadmaps. A feature in
Cited Cloud does not automatically belong in the public repository, and vice
versa.

See [ROADMAP.md](ROADMAP.md) for high-level public milestones.

## Community expectations

- No guaranteed response time or merge timeline is promised.
- Contributors are not entitled to employment, compensation, sponsorship, or
  commercial rights in Cited Cloud.
- Participation is governed by [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## Evolution

Governance may evolve as the community grows. Material changes should be
documented in this file with rationale.

## Escalation

For conduct concerns, see [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

For security concerns, see [SECURITY.md](SECURITY.md).

For general questions before publication, use https://cited.cc/contact.
